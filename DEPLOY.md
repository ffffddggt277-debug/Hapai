# Деплой: Render + Vercel

Проект ещё **не опубликован в ваших аккаунтах**. Ниже настройки для исходников из архива. Можно хранить всё в одном GitHub-репозитории.

## 1. GitHub

Создайте пустой репозиторий (например, `hapai`). Распакуйте ZIP, откройте терминал в папке с package.json и выполните:

```bash
git init
git add .
git commit -m "Hapai v2.0"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/hapai.git
git push -u origin main
```

Замените YOUR_ACCOUNT. Авторизуйтесь обычным безопасным способом GitHub. **Модели (.glb) и Blender-исходники (.blend, .py) тоже должны попасть в репозиторий. Не включайте API-токены в файлы, коммиты или .env.example.** Папки node_modules, .next и реальные .env в репозиторий не попадают.

## 2. Сервер на Render

Render Dashboard → New → Web Service → подключить репозиторий.

| Настройка | Значение |
|---|---|
| Runtime | Node |
| Branch | main |
| Root Directory | **оставить пустым: корень репозитория** |
| Build Command | `npm ci --workspace=@hapai/server --workspace=@hapai/shared --include-workspace-root` |
| Start Command | `npm run start:server` |
| Health Check Path | `/health` |
| Instances | **1** |
| Region | ближе к игрокам |
| Plan | Free для пробы; постоянно работающий платный инстанс для стабильных матчей |

Environment Variables:

```text
NODE_ENV=production
FRONTEND_URL=https://YOUR_PROJECT.vercel.app
```

Если клиентский домен пока неизвестен, временно можно использовать `http://localhost:3000`, а после Vercel **обязательно заменить** и передеплоить. PORT устанавливает Render; вручную не нужен. Сервер слушает 0.0.0.0.

После запуска сохраните HTTPS-адрес сервиса, например `https://YOUR_SERVER.onrender.com`. Откройте `/health`: ожидается `{"ok":true,"version":"2.0.0"}`.

В репозитории есть render.yaml: можно вместо ручной формы выбрать New → Blueprint. FRONTEND_URL будет запрошен отдельно.

**Важно:** Free-сервис засыпает после 15 минут без входящего трафика, включая WebSocket-сообщения. Пробуждение занимает около минуты. Self-ping здесь намеренно отсутствует и не обещается как способ обойти ограничения. Сон/рестарт обнуляет текущие комнаты. Не запускайте несколько инстансов этого прототипа.

## 3. Клиент на Vercel

Vercel → Add New → Project → тот же GitHub-репозиторий.

| Настройка | Значение |
|---|---|
| Framework Preset | Next.js |
| Root Directory | `apps/client` |
| Build Command | `npm run build` (обычный Next.js build для выбранного workspace) |
| Output Directory | стандарт Next.js: **не менять** |
| Install Command | стандартное автоматическое определение npm/монорепозитория |
| Node.js Version | 24.x (или поддерживаемая платформой 22.x) |

Vercel должен иметь доступ к соседнему `packages/shared` и корневым package.json/package-lock.json. Если настройка «Include source files outside of the Root Directory» показана, **включите её**. Это монорепозиторий npm workspaces. Не загружайте одну папку apps/client отдельно: ей нужен общий пакет карты.

До первого Deploy добавьте Environment Variable для Production:

```text
NEXT_PUBLIC_SERVER_URL=https://YOUR_SERVER.onrender.com
```

Значение должно быть HTTPS-URL без `/health`. Это публичный адрес, не секрет. Переменная NEXT_PUBLIC_* встраивается **при сборке**: после изменения необходим новый деплой клиента.

Получите адрес клиента и вернитесь в Render:

```text
FRONTEND_URL=https://YOUR_PROJECT.vercel.app
```

Сохраните и дождитесь перезапуска сервера. В адресе Origin не должно быть конечного слэша и пути.

## 4. Проверка

1. `/health` сервера отвечает.
2. Открыть клиент в двух разных браузерах/вкладках.
3. Создать комнату, скопировать ссылку, во второй вкладке войти.
4. Убедиться, что в лобби два участника, оба готовы, начать.
5. Проверить движение, обзор за стеной, взлом витрины (держать E) → сирена и дроны, шкаф (5 с), толчок, рывок, вынос добычи через открытый выход.
6. Открыть на телефоне: стик, свайп взгляда, кнопки «Действие», «Толчок», «Рывок».
7. При ошибке проверить Render Logs и Console/Network браузера.

`NEXT_PUBLIC_SERVER_URL` использует адрес сервера, `FRONTEND_URL` — адрес клиента: не перепутайте их. Для нескольких разрешённых адресов на Render используйте список через запятую:

```text
FRONTEND_URL=https://YOUR_PROJECT.vercel.app,https://play.your-domain.com
```

Не разрешайте все `.vercel.app` домены: чужой сайт тоже мог бы подключаться. Preview-деплои Vercel надо добавлять конкретными origin, если они действительно нужны для теста. Сервер проверяет Origin для WebSocket, не только HTTP CORS. Origin не заменяет аутентификацию: нативный клиент способен его подделать.

## 5. Настраиваемый адрес

Можно использовать свободный адрес проекта `YOUR_PROJECT.vercel.app`, который предоставляется платформой. Точное имя зависит от доступности и настроек аккаунта.

Для собственного адреса (примеры, **не уже зарегистрированные адреса игры**):

```text
play.your-domain.com  → Vercel, клиент
api.your-domain.com   → Render, сервер
```

1. Купить/использовать свой домен.
2. Vercel → проект → Settings → Domains → добавить клиентский адрес.
3. У регистратора DNS добавить **точные записи, показанные Vercel**. Не копировать случайные старые IP-адреса из туториалов.
4. Для серверного домена: Render → сервис → Settings → Custom Domains; добавить адрес и его DNS-запись по инструкции панели. Собственный серверный домен необязателен: можно оставить onrender.com.
5. Дождаться проверки DNS и TLS.
6. На Render добавить новый клиентский origin в FRONTEND_URL. Если сменили серверный адрес, поменять NEXT_PUBLIC_SERVER_URL в Vercel и пересобрать клиент.

Домен оплачивается отдельно. Публикация сайта не требует собственного домена.

## 6. Если деплой делает ассистент

Нужно предоставить/согласовать:

- GitHub-репозиторий с правом записи или безопасно авторизовать GitHub.
- Доступ к нужному аккаунту/team Vercel и workspace Render через подключённую интеграцию, авторизацию либо **ограниченные API-токены в защищённом запросе**. Пароли, токены и коды 2FA не отправлять обычным сообщением.
- Имена проекта/сервиса, регион и разрешённый тариф. Платные сервисы не создаются без отдельного согласования расходов.
- При своём домене — название домена и возможность изменить DNS (безопасная авторизация у регистратора либо вы вносите показанные записи самостоятельно).

Для бесплатного первого запуска достаточно GitHub + Render + Vercel; карта и домен не обязательны, если сами платформы их не запросят для аккаунта. Возможность автоматического деплоя зависит от доступных прав и способов авторизации; passkey-only или требования управляемого устройства могут не поддерживаться удалённой средой.
